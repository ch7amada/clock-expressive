# Review F01 (round 1)
Verdict: CHANGES_REQUESTED

## Findings
1. [MAJOR] app/src/main/kotlin/org/fossify/clock/ui/theme/Type.kt:25-38 — Emphasized styles render in the default system font, not Google Sans Flex. `val DefaultTypography = Typography()` (line 23, default font family) is used as the source for each `.copy(fontWeight = …)`, so every `*Emphasized` style's `fontFamily` is replaced with the default family. The base `Typography(fontFamily = GoogleSansFlex)` is discarded for these 12 styles, breaking the spec ("applies the family to all 30 styles, incl. *Emphasized") and acceptance criterion "Google Sans Flex everywhere." Required change: copy the emphasized styles from a `GoogleSansFlex` base so the family is preserved and only the weight changes, e.g.
   ```kotlin
   private val FlexBase = Typography(fontFamily = GoogleSansFlex)
   val ClockTypography = FlexBase.copy(
       displayLargeEmphasized = FlexBase.displayLargeEmphasized.copy(fontWeight = FontWeight.Bold),
       … /* same pattern for the other 11, using FlexBase.<style> */
   )
   ```
2. [MINOR] app/src/main/kotlin/org/fossify/clock/ui/theme/Theme.kt:26 — `DisposableEffect(config)` keys on `config`, but `Context.config` returns a **new** `Config` on every access (`extensions/Context.kt:91-92`), so the key changes identity on each recomposition and the prefs listener is unregistered/re-registered each time (churn, plus a tiny window where a pref change can be missed). Required change: stabilize the key with `val config = remember { LocalContext.current.config }` before the `DisposableEffect`.
3. [MINOR] app/src/main/kotlin/org/fossify/clock/ui/theme/ThemePreview.kt:47 — Icon-only `MediumFloatingActionButton` uses `contentDescription = null`; AGENTS.md requires every icon-only control to have a `contentDescription` from a string resource. Required change: `contentDescription = stringResource(R.string.<m3e_…>)` with a new `m3e_` string added to `res/values/strings.xml`. (Preview-only, hence MINOR.)

## PM addendum (orchestrator)
4. [BLOCKER] app/src/main/kotlin/org/fossify/clock/ui/theme/Theme.kt `rememberThemeSettings()` — `val settings = mutableStateOf(...)` is **not
   remembered**: every recomposition creates a fresh state object, while the listener registered in the `DisposableEffect` keeps writing to the
   first one, so theme changes stop applying after the first recomposition. Required change:
   `val config = remember(context) { context.config }`, `var settings by remember { mutableStateOf(readThemeSettings(config)) }`,
   `DisposableEffect(config) { ... }` (this also fixes finding 2).
5. [MINOR] `isAppInDarkTheme()` duplicates the dark-mode `when`; extract a private `@Composable fun ThemeSettings.isDark(): Boolean` and use it in both places.
