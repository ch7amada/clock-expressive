## Findings
1. [MINOR] app/src/main/kotlin/org/fossify/clock/ui/clock/ClockScreen.kt:120-124 — the hero scale-in (`remember { Animatable(0.92f) }` + `LaunchedEffect(Unit)`) lives inside the first `item {}` of the LazyColumn; when the hero scrolls out of range (e.g. user scrolls to the world-clock rows) and back, the item composition is discarded and the 0.92→1.0 scale-in animates again. Hoist the `Animatable` and `LaunchedEffect` to the `ClockScreen` level (outside the `item {}`) so the animation only runs on first composition.
2. [MINOR] app/src/main/kotlin/org/fossify/clock/ui/clock/HeroClock.kt:43-50 — spec says "Use java.time (…) and DateTimeFormatter for the strings"; implementation uses `String.format(locale, …)` instead. Output is equivalent for these patterns, but switch to `DateTimeFormatter.ofPattern("HH:mm")` / `"h:mm"` (with `Locale.getDefault()`) to match the spec.
3. [MINOR] app/src/main/kotlin/org/fossify/clock/ui/clock/HeroClock.kt:82 — `RoundedCornerShape(50)` uses the percentage constructor (50% of the smaller side); it does render as a pill but the intent is opaque. Use `CapsuleShape` (or `RoundedCornerShape(50.dp)`) to state the pill explicitly.
4. [MINOR] app/src/main/kotlin/org/fossify/clock/ui/clock/ClockScreen.kt:156 — no haptic on the next-alarm chip click (or the FAB at 103); AGENTS.md asks for haptics on important actions and the repo's own precedent is `ClockApp.kt:92` (`SegmentTick`) / `Shapes.kt:286`. Add `LocalHapticFeedback.current.performHapticFeedback(HapticFeedbackType.Confirm)` to both click handlers.
