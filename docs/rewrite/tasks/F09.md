# F09 — Sound picker sheet (shared by the alarm and timer editors)

## Goal
A Compose replacement for Fossify's `SelectAlarmSoundDialog`: a bottom sheet listing **your sounds** (custom audio files),
**No sound**, the **default** sound, and all **system alarm sounds**, with live preview playback, "Add new sound" via the
system document picker, and removal of custom sounds. It is used by F10 (alarm editor) and F14 (timer editor).

## Read first
- `docs/rewrite/legacy/commons/SelectAlarmSoundDialog.kt` (167 lines — the behaviour to replicate)
- Facts from Fossify commons (verified, do not look them up):
  - `org.fossify.commons.models.AlarmSound(id: Int, title: String, uri: String)`
  - `org.fossify.commons.helpers.SILENT` = `"silent"` (uri of "No sound"); `YOUR_ALARM_SOUNDS_MIN_ID` = 1000
  - `config.yourAlarmSounds: String` — a JSON `ArrayList<AlarmSound>` (Gson; use `com.google.gson.Gson` and `TypeToken` like the legacy code)
  - `Context.getDefaultAlarmSound(type: Int): AlarmSound` (`org.fossify.commons.extensions`)
  - `Context.storeNewYourAlarmSound(resultData: Intent): AlarmSound` (`org.fossify.commons.extensions`). It takes the
    persistable URI permission and appends to `config.yourAlarmSounds`.
  - strings: `org.fossify.commons.R.string.no_sound`, `.add_new_sound`, `.alarm_sound` (if missing, grep `strings.xml` or add `m3e_`)
  - The app already has `Context.checkAlarmsWithDeletedSoundUri(uri)` in `extensions/Context.kt`.
- `docs/rewrite/api/ModalBottomSheet.md`, `docs/rewrite/api/RadioButton.md`; `ui/components/Lists.kt`, `ui/components/Shapes.kt` (signatures)

## Create `ui/components/SoundPicker.kt`

```kotlin
@Composable
fun SoundPickerSheet(
    currentUri: String,
    type: Int,                       // RingtoneManager.TYPE_ALARM (alarms) or TYPE_ALARM too for timers
    onSoundPicked: (AlarmSound) -> Unit,
    onSoundDeleted: (AlarmSound) -> Unit,   // caller resets its selection if it was the deleted one
    onDismiss: () -> Unit,
    loopPreview: Boolean = false,
)
```
- Load system sounds on `Dispatchers.IO`, exactly like commons `getAlarmSounds`: default first, then "No sound"
  (`SILENT`), then the `RingtoneManager(context).apply { setType(type) }.cursor` rows (append `/$id` to the URI when it does
  not already end with it). On exception, show an empty list and a toast (`showErrorToast` from commons, or a `Toast`).
- Your sounds: parse `config.yourAlarmSounds`, plus an "Add new sound" row (leading `ShapeBadge(MaterialShapes.Flower)` with `Icons.Rounded.Add`).
- Layout: `ModalBottomSheet` → title (`headlineSmallEmphasized`) → `LazyColumn` with `SectionHeader("Your sounds")` +
  `segmentedGroup` rows and `SectionHeader(system)` + `segmentedGroup` rows. Each row is a `SegmentedListItem(selected = uri == selectedUri, onClick = …)`
  with a trailing `RadioButton`, and the selected row shows an animated equaliser/`Icons.Rounded.GraphicEq` leading icon while
  preview is playing.
- Clicking a sound selects it and **previews** it with `MediaPlayer` (`AudioAttributes.USAGE_ALARM`, `isLooping = loopPreview`);
  SILENT stops playback. Release the player in `DisposableEffect` `onDispose` and when the sheet closes.
- "Add new sound": `rememberLauncherForActivityResult(ActivityResultContracts.OpenDocument())` with `arrayOf("audio/*")`.
  On result, build an `Intent().setData(uri).addFlags(FLAG_GRANT_READ_URI_PERMISSION or FLAG_GRANT_PERSISTABLE_URI_PERMISSION)`, call
  `context.storeNewYourAlarmSound(intent)`, reload your sounds, and select the new sound.
  (Check the legacy file for how the old code produced the Intent; mirror it.)
- Long-press on a custom sound → `ConfirmDialog` → remove it from `config.yourAlarmSounds` (as `removeAlarmSound` does),
  call `context.checkAlarmsWithDeletedSoundUri(sound.uri)` on IO, then `onSoundDeleted(sound)`.
- Bottom: a full-width `Button(shapes = ButtonDefaults.shapes())` "OK" → `onSoundPicked(selected)` then `onDismiss()`.
  Dismissing without OK does not change the selection.
