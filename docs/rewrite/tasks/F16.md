# F16 — Settings in Compose (expressive grouped lists)

## Goal
Rewrite `SettingsActivity` as a Compose screen with expressive **segmented list groups**. Port every setting and its
behaviour from the current activity, and **replace the Fossify color customisation** with the new Material theme settings
(theme mode, dynamic color, pure black) from F01.

## Read first
- `app/src/main/kotlin/org/fossify/clock/activities/SettingsActivity.kt` (363 lines — all; it's the spec of behaviours)
- `app/src/main/kotlin/org/fossify/clock/dialogs/ExportDataDialog.kt` (76 lines — only the default file-name logic)
- `app/src/main/kotlin/org/fossify/clock/ui/theme/Theme.kt` (`ThemeSettings`), `helpers/Constants.kt` (grep `THEME_MODE`)
- signatures: `ui/components/Lists.kt`, `ui/components/Dialogs.kt`, `ui/components/Shapes.kt`
- `docs/rewrite/api/ListItem.md` (grep `SegmentedListItem`), `docs/rewrite/api/AppBar.md` (`LargeFlexibleTopAppBar`), `docs/rewrite/api/SegmentedButton.md`

## Create

### `ui/settings/SettingsScreen.kt`
`@Composable fun SettingsScreen(state: SettingsUiState, actions: SettingsActions, onBack: () -> Unit)`, stateless. A `LargeFlexibleTopAppBar`
(title `org.fossify.commons.R.string.settings`, back arrow) with `exitUntilCollapsedScrollBehavior`, and a `LazyColumn` of groups built with
`SectionHeader` + `segmentedGroup`. Every row is a `SegmentedListItem` with a leading icon in a 40.dp `ShapeBadge` (each group uses a
different `MaterialShapes` polygon and container color: Appearance `Cookie9Sided`/primaryContainer, General `Clover4Leaf`/secondaryContainer,
Alarms `Sunny`/tertiaryContainer, Timers `Cookie6Sided`/secondaryContainer, Data `Pill`/surfaceContainerHighest), a headline, a
supporting value, and a trailing `Switch` for booleans.

Groups and rows:
1. **Appearance** (new): Theme — a 3-option connected `ButtonGroup`/`SingleChoiceSegmentedButtonRow` (System / Light / Dark; new `m3e_` strings);
   Dynamic color — switch, shown only on API 31+; Pure black — switch, enabled only when dark is possible.
2. **General**: Language (API 33+: `launchChangeAppLanguageIntent()`), Use English (same visibility rule; `exitProcess(0)` after toggle),
   Default tab (`RadioListDialog` with clock/alarm/stopwatch/timer/last-used, as old), 24-hour format (switch + `updateWidgets()`),
   Prevent phone from sleeping, Start week on (`RadioListDialog` of the 7 days).
3. **Alarms**: Alarm max reminder duration, Use same snooze (switch; reveals Snooze time with `AnimatedVisibility`), Snooze time,
   Increase volume gradually.
4. **Timers**: Timer max reminder duration.
5. **Widgets**: Customize widget colors → `WidgetDigitalConfigureActivity` with `IS_CUSTOMIZING_COLORS`.
6. **Data**: Export alarms and timers, Import alarms and timers.

Use the existing string resources from the old layout (`grep -n 'settings_\|name="' res/layout/activity_settings.xml` to find which strings it used,
then reuse them).

### `ui/settings/DurationPickerDialog.kt`
`@Composable fun DurationPickerDialog(title: String, currentSeconds: Int, options: List<Int>, allowSeconds: Boolean, onPick: (Int) -> Unit, onDismiss: () -> Unit)`
— a `RadioListDialog`-like list of preset durations (format with commons `formatSecondsToTimeString` / `formatMinutesToTimeString`, the same helpers the activity uses)
plus a "Custom" option with a number field (minutes, or seconds when `allowSeconds`). Presets: snooze = 1, 5, 10, 15, 20, 30 min; max reminder = 1, 5, 10, 15, 20, 30 min.
Keep the old fallback rule (0 → the `DEFAULT_MAX_*` constants).

### Rewrite `activities/SettingsActivity.kt`
Keep it a `SimpleActivity`. `enableEdgeToEdge()` + `setContent { ClockTheme { SettingsScreen(...) } }`. Keep both `registerForActivityResult`
launchers and the `exportData`/`importData` functions **unchanged** (they run on a background thread). Replace `ExportDataDialog` with a small
Compose dialog to edit the file name (default from the same logic), then `exportActivityResultLauncher.launch(fileName)`. State lives in a
`mutableStateOf(SettingsUiState(...))` that is re-read from `config` in `onResume` and after every change. Remove view-binding usage.
