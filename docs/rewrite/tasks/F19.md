# F19 — IntentHandlerActivity dialogs + permission rationale in Compose

## Goal
The last View-based dialogs are shown when other apps or the assistant send `AlarmClock` intents (`IntentHandlerActivity`), and
for permissions (`PermissionRequiredDialog` from commons, used in `extensions/Activity.kt` and `MainActivity`). Port them to Compose
using the editors and components that already exist, so the whole app looks Material 3 Expressive.

## Read first
- `app/src/main/kotlin/org/fossify/clock/activities/IntentHandlerActivity.kt` (424 lines: read lines 1–90 and 290–424; grep the rest as needed)
- `app/src/main/kotlin/org/fossify/clock/dialogs/SelectAlarmDialog.kt` (55 lines)
- `app/src/main/kotlin/org/fossify/clock/extensions/Activity.kt` (42 lines)
- signatures: `ui/alarm/AlarmEditorSheet.kt`, `ui/timer/TimerEditorSheet.kt`, `ui/components/Dialogs.kt`, `ui/theme/Theme.kt`
- How the activity is themed: grep `IntentHandlerActivity` in `app/src/main/AndroidManifest.xml` (it must stay transparent/dialog-like)

## Implement

### `ui/components/PermissionDialog.kt`
`@Composable fun PermissionRationaleDialog(text: String, onOpenSettings: () -> Unit, onDismiss: () -> Unit)` — expressive `AlertDialog` with a
`ShapeBadge(MaterialShapes.Burst)` + `Icons.Rounded.NotificationsActive` icon, title "Permission required" (commons `permission_required` string
if it exists), the text, and "Grant" / "Cancel" buttons (`org.fossify.commons.R.string.grant_permission` / `cancel`, or `m3e_` fallbacks).

### A Compose dialog host for activities
`ui/components/DialogHost.kt`: an object `ComposeDialogs` with `fun ComponentActivity.showComposeDialog(content: @Composable (dismiss: () -> Unit) -> Unit)`
that adds a `ComposeView` (with `ClockTheme`) to `android.R.id.content` (once) and renders the given dialog until `dismiss()` removes it.
This lets non-Compose call sites (like `handleFullScreenNotificationsPermission`) show Compose dialogs without changing their callback API.

### `extensions/Activity.kt`
Replace both `PermissionRequiredDialog(...)` calls with `showComposeDialog { dismiss -> PermissionRationaleDialog(...) }` and identical callbacks
(positive → open settings; negative and dismiss → `notificationsCallback(false)`, called exactly once).

### `IntentHandlerActivity`
- `openEditAlarm` → `showComposeDialog { dismiss -> AlarmEditorSheet(initial = alarm, use24h = config.use24HourFormat, onSave = { a -> insert or update on IO (as AlarmViewModel.saveAlarm does), set alarm.id, startAlarm(a), finish() }, onDelete = null, onDismiss = { dismiss(); finish() }) }`.
- `openEditTimer` → `TimerEditorSheet` similarly (save → `insertOrUpdateTimer` → `timer.id = id` → `startTimer(timer)`).
- `SelectAlarmDialog` → `RadioListDialog` of the alarms (label, or the formatted time if the label is empty), same callbacks (`null` on dismiss).
- `PermissionRequiredDialog` in `startTimer` → `PermissionRationaleDialog` with the same positive and negative behaviour.
- Remove the now-unused imports. Do not delete the old dialog classes (the PM does that in F20).

## Acceptance criteria
- [ ] `tools/agents/compile.sh` → `COMPILE OK`
- [ ] `adb shell am start -a android.intent.action.SET_ALARM` (without `EXTRA_SKIP_UI`) shows the Compose alarm editor; saving schedules it and finishes.
- [ ] `SET_TIMER` without a length shows the timer editor; with a length it starts directly (unchanged).
- [ ] `DISMISS_ALARM` with several matches shows the Compose selection dialog.
- [ ] Permission flows behave exactly as before, with callbacks invoked once.
